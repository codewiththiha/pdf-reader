## 0.8.0

### The library

- The shelf is a library now, not a list of what you opened last. You make a shelf, name it, file
  books into it and file a shelf inside a shelf. The breadcrumb is the chain you are standing on,
  and a chain deeper than the bar is wide folds behind three dots rather than scrolling off it.
- The bar keeps its own memory: the columns you asked for, the sort, the view. A knob that only
  paints the shelf is on the bar; a knob that changes what the library holds is on a sheet.
- A folder's card is a plate of the covers inside it, so a folder reads as the tree it holds
  rather than as a rectangle with a name on it. Covers that fail to arrive are retried by the
  library itself, and a plate whose books have not rendered yet says it is waiting rather than
  showing four grey squares.

### Watched folders

- Import a folder and the library watches it. A rescan reconciles what is on disk with what is on
  the shelf: books that arrived are shelved, books that left are marked, and a folder nothing
  changed in leaves no trace beyond its own "last scanned" stamp.
- The folder keeps a ledger. It remembers what it placed and what it was told to ignore, which is
  what makes re-importing safe: a book you removed last week is not handed back to you by a
  rescan, because the ledger still says you removed it.
- A removal is remembered as a tombstone, and a tombstone is an offer. The folder's restore menu
  reads its own log and can put a book back — in the name the shelf showed, on the shelf it stood
  on. A book that comes back is lit rather than announced: the import succeeded by making it
  reappear where the folder holds it, and a highlight says that without a sentence.
- A book you move back into the folder by hand is recognised as the book you removed, not imported
  beside it as a second copy.

### Read in place, or copy

- A folder can be read where it lies, or copied into the library's own storage. Read in place and
  the shelf points at your files; copy and the library owns the bytes, so a file that moves or is
  deleted elsewhere cannot take a book off your shelf.
- A folder that was read in place can be switched to copies later, and the switch asks which of
  three things you meant: an **as new** tree of its own beside the one you have, a **merge** into
  the shelf that stands, or a **replace** of it. An as new run owes its tree copies of its own —
  independent books, with their own marks and their own place — because a second instance you
  asked for by name is not the same book as the first.
- A loose file you drop on the library lands as the library's own copy. There is no folder to
  read in place, and a single file the library does not own is a book that can vanish.

### One book, one row

- Identity is the file's content, not its address. The same PDF opened twice, dropped twice or
  imported from two folders is one book on the shelf, and the second arrival is filed beside the
  first rather than duplicated.
- A link is the exception, and it is explicit: one file can be two books when you ask for two, and
  the second is a book of its own — its own marks, its own place, its own progress. The library
  remembers which books are independent, so a rescan does not fold them back into one.
- A book a folder read in place that is later copied keeps its place on the shelf. The conversion
  happens under the row, not beside it.

### Importing

- The folder sheet asks before it walks: whether the folder is new, continues one you have, or
  replaces it — and, for a folder that is already here, whether the tree it found is its own,
  merged into the shelf that stands, or a replacement for it.
- A merge asks per file wherever two names meet. A file whose name a standing shelf already holds
  gets the three answers — one book, replace, or as new — one at a time or one answer for all of
  them. Files nothing collides with join silently, because a new book in a merged folder is the
  default and not a case.
- A planned tree holds every book the folder has, not only the new ones: the files the library
  already held are filed into the tree as memberships of the rows it holds them in, so a
  re-import of a folder whose every file is known still produces the tree you asked for.
- Dropping a file on the library lands it on the level you dropped it on, and the import sheet
  unfolds the path it is about to import so you can see what will be made before it is.

### Removal is a receipt

- Removing says what left, and offers it back. A shelf removed with books inside it is taken
  apart in the receipt, so what you get back is the set that actually went rather than a number.
- A book that leaves a watched folder leaves as the library's own copy, so removing it from the
  shelf does not delete the file you imported it from — and the folder's log knows the way back.
- Cancelling a collision sheet drops the question on screen and every one waiting behind it,
  which is what a file manager's copy dialog has always meant by Cancel: the placements already
  answered keep their answers, and the ones not asked simply do not land.

### Search the shelf

- The library's search answers as it is typed, fuzzy, ranked, with suggestions under the bar. A
  title that is a filename is not treated as a title, and a query that matches nothing says so
  rather than showing an empty grid.
- The search rule and its panel are one rule: what the suggestion list ranks is what the shelf
  filters on, so an answer you can see in the panel is an answer you can reach from it.

### Drag, hold and the set

- Hold a book to select it, and act on the set. A press decides once what it meant — a hold, a
  drag or a click — so the three cannot race and a finger cannot both select and drag the same
  press.
- A drag out of a branch lifts the branch, not the page, and a rest folds a set into a shelf.
  Every shelf row has the shelf's whole gesture, and every list row a target and a container, so
  a drop lands where the edges say it will.
- The shelf's drag is the app's own, not the browser's: no drag image from the compositor, no
  half-rendered ghost, and a drop that is a library decision rather than a file-manager one.

### Under the hood

- `library-core` holds the rules and nothing else: identity, shelves, the rescan ledger, the
  collision's three answers and the filename arithmetic. It is a crate with no platform in it, so
  every rule in this release is a rule a test can call — `cargo test -p library-core` runs them on
  the host, with no browser, no shell and no filesystem.
- The library's surfaces read their facts back by id rather than by carrying them, so a card, a
  row and a menu cannot disagree about the book they are all showing.
- A persisted library is validated on load and the validation is idempotent: a shelf whose member
  names no book drops the member, a folder shelf goes with its folder, and two rows sharing an id
  leave one book and one member.
- The reader's settings modal rides the same shell every other sheet rides, so one dialog in the
  app cannot have a different escape key, a different backdrop or a different heading from the
  rest.
